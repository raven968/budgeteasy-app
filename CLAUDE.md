# BudgetEasy App

Mobile app (Expo SDK 58, React Native, TypeScript) for BudgetEasy: shared budgets and expense tracking between people (e.g. a couple). It consumes the BudgetEasy API (Laravel), which lives in its own repository (`budgeteasy-api`).

@AGENTS.md

## Domain rules (enforced by the API, mirrored in the UI)

- A user can own N budgets and be a member of budgets shared with them (`role`: `owner` | `member`).
- Categories belong to the user (max 10 active, `meta.max` in the API). A shared budget uses its owner's categories; only the owner manages them.
- Expenses: any member registers them; the author or the budget owner can edit/delete.
- Sharing: the owner generates a 6-character code (48h, single use); another user joins with it.
- **Money is always integer cents** in the API (`150000` = $1,500.00). Convert only at the UI edge (input/format).
- Dates: `spent_on` is `YYYY-MM-DD`; month filters are `YYYY-MM`.

## Conventions (mandatory)

- **API data keeps the API's snake_case** keys everywhere in the app (`budget.spent_amount`, `expense.spent_on`), including TypeScript types and form payloads sent to the API.
- **Every variable, function, hook and prop declared in the app uses camelCase** (`const remainingAmount = ...`). Components and types use PascalCase.
- Follow React best practices: function components, hooks, no business logic inside screens beyond composition, derived state over duplicated state.
- Code is organized by feature under `src/features/<feature>/` (`api.ts`, `hooks.ts`, `components/`, `types.ts`). Routes/screens live only in `src/app/` (Expo Router). Shared code in `src/lib/` and `src/components/`.
- Server state with TanStack Query (the auth session is the `['session']` query); forms with react-hook-form + zod, with API errors applied through `applyApiErrors`.
- Styling with `StyleSheet` and the tokens in `src/lib/theme.ts` read via `useTheme()`; no hard-coded colors or spacing. Reuse `src/components` (`Screen`, `ThemedText`, `TextField`, `Button`).
- Routes: `src/app/(auth)` for signed-out screens, `src/app/(app)` for signed-in ones, guarded in the root layout with `Stack.Protected`.
- File names in kebab-case (`token-storage.ts`, `update-required-screen.tsx`), as in the Expo template.
- UI strings always go through i18next (`src/lib/i18n/locales/{es,en}.json`); never hard-code user-facing text.
- **Package manager: pnpm** (never npm/npx/yarn). This overrides the `npx` commands in AGENTS.md:
  - Install: `pnpm expo install <pkg>` (dev tools: `pnpm expo install <pkg> -- --save-dev`).
  - One-off tools: `pnpm dlx <tool>` (e.g. `pnpm dlx expo-doctor`, `pnpm dlx eas-cli@latest build`).
  - Run before finishing a task: `pnpm lint`, `pnpm typecheck`, `pnpm test`.
  - `pnpm-workspace.yaml` sets `minimumReleaseAge` (no versions younger than 1 day). Dependency build scripts stay blocked; approve one with `pnpm approve-builds` only if something actually breaks without it.
- TypeScript 6 does not load `@types/*` automatically: add new global type packages to `compilerOptions.types` in `tsconfig.json`.

## API

- Base URL from `EXPO_PUBLIC_API_URL` (`.env`, see `.env.example`).
- Auth: Sanctum Bearer token stored in `expo-secure-store`.
- Send `Accept-Language` with the app language (`es` default, `en`).
- Reference: the API docs at `http://budgeteasy.test/docs/api` (local, generated by Scramble).

## Versioning

- Semantic Versioning. `package.json` `version` is the single source of truth for the app version.
- Update `CHANGELOG.md` (Keep a Changelog) and create the git tag `vX.Y.Z` on each release.
- The API exposes `min_mobile_version` in `GET /api/v1/version`; the app forces an update when its version is lower.
- Commits follow Conventional Commits. Work goes directly to `main` until beta / v1.0.0.
